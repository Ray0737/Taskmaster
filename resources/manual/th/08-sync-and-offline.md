# การซิงก์และการใช้งานออฟไลน์

มีสองอย่างที่ซิงก์: โค้ดของคุณ (Source Control → ซิงก์) และข้อมูลทีม (อัตโนมัติ) บทนี้เกี่ยวกับข้อมูลทีม

## ข้อมูลทีมอยู่ที่ไหน

บน branch `taskmaster/context` ในโฟลเดอร์ `.taskmaster/`:

- `team.json` — หัวหน้า สมาชิก บทบาท
- `tasks/<id>.json` — หนึ่งไฟล์ต่อหนึ่งงาน
- `notes/<id งาน>/…md` — หนึ่งไฟล์ต่อหนึ่งโน้ต ไม่ถูกแก้ภายหลัง
- `presence/<login>.json` — ใครออนไลน์ เขียนโดยเจ้าตัวเท่านั้น

Taskmaster checkout branch นี้ไว้ในโฟลเดอร์แยกภายในโฟลเดอร์ข้อมูลของแอป (`%APPDATA%\taskmaster\worktrees`) โฟลเดอร์โปรเจกต์และ branch ปัจจุบันของคุณจึงไม่ถูกเปลี่ยน

## ซิงก์อย่างไร

- ประมาณ 3 วินาทีหลังคุณเปลี่ยนอะไร ระบบจะ commit (ข้อความ `tm: <login> …`) และ push
- ทุก 15 วินาที (30 หรือ 60 ได้ใน **การตั้งค่า → ซิงก์**) ระบบ fetch สิ่งที่เพื่อนร่วมทีมทำและรวมให้ มุมมองงานและทีมอัปเดตเอง
- สถานะออนไลน์ของคุณถูกรีเฟรชทุกนาที

ถ้าสองคนแก้ไฟล์เดียวกันพร้อมกัน ฝั่งคุณจะใช้เวอร์ชันของคุณ และการ push ครั้งหลังสุดชนะสำหรับทุกคน โน้ตและสถานะออนไลน์ไม่ชนกันเพราะแต่ละไฟล์มีคนเขียนคนเดียว

## แถบสถานะ

รายการทางซ้ายแสดงจำนวนคนออนไลน์ ไอคอนและคำอธิบายแสดงสถานะ:

- เป็นปัจจุบัน
- กำลังซิงก์
- **ออฟไลน์** — ไม่มีเครือข่ายหรือไม่มีสิทธิ์ การเปลี่ยนแปลงของคุณถูกเก็บไว้และจะ push ทันทีที่ใช้ได้อีกครั้ง Taskmaster ลองใหม่หลัง 15 วินาที แล้ว 30 วินาที 1 นาที 2 นาที และทุก 5 นาที คลิกรายการเพื่อลองเดี๋ยวนี้
- **ซิงก์ขัดแย้ง** (สีแดง) — รวมข้อมูลทีมอัตโนมัติไม่ได้ คลิกแล้วเลือก **รีเซ็ตเป็นเวอร์ชันบนเซิร์ฟเวอร์** เพื่อทิ้งการเปลี่ยนแปลงทีมที่ยังไม่ซิงก์ของคุณและใช้เวอร์ชันบนเซิร์ฟเวอร์
- หยุดชั่วคราว — ปิดไว้ในการตั้งค่า → ซิงก์ เอาติ๊กออกเพื่อทำต่อ

## ซ่อมด้วยมือ

ทุกอย่างคือ git ธรรมดา: ตรวจ branch ได้ด้วย `git log origin/taskmaster/context` และดูไฟล์ด้วย `git show origin/taskmaster/context:.taskmaster/team.json` ไฟล์ที่เสียหายจะถูกแอปข้ามไปเฉย ๆ
