# ทีมและบทบาท

Taskmaster เก็บบทบาท งาน โน้ต และสถานะออนไลน์ของทีมไว้ใน git repository เดียวกับโปรเจกต์ บน branch แยกชื่อ `taskmaster/context` branch นี้ไม่ปนกับ branch โค้ดของคุณ และโฟลเดอร์ทำงานของคุณจะไม่ถูกแตะต้อง

## เปิดใช้ Taskmaster

เปิดมุมมอง ทีม (หรือ งาน) ถ้าโปรเจกต์ยังไม่มีข้อมูลทีมจะเห็น **เปิดใช้ Taskmaster** (และเป็นแถบเหนือตัวแก้ไขด้วย) สิ่งที่ต้องมี:

- remote ชื่อ `origin` (โปรเจกต์ใหม่: ติ๊ก "สร้าง GitHub repository" หรือ push ด้วย การควบคุมต้นฉบับ → ซิงก์ ก่อน)
- อย่างน้อยหนึ่ง commit

คุณจะเป็น **หัวหน้า** และสมาชิกคนแรก เพื่อนร่วมทีมที่เปิด repository เดียวกันภายหลังจะเข้าร่วมเองเมื่อเปิดครั้งแรก

## สมาชิก

มุมมองทีมแสดงทุกคนพร้อมบทบาทและสิ่งที่กำลังทำ: **กำลังทำ "งาน"**, **ว่าง** หรือ **ออฟไลน์** คุณถือว่าออนไลน์เมื่อแอปของคุณส่งสัญญาณภายใน 3 นาทีที่ผ่านมา

**เพิ่มสมาชิก** (ไอคอนรูปคน): พิมพ์ GitHub login หรือเลือกจากผู้ร่วมพัฒนาของ repository ถ้าคุณล็อกอิน GitHub อยู่ Taskmaster จะส่งคำเชิญเข้า repository ให้ ถ้าไม่ จะเพิ่มคนนั้นเข้าทีมเท่านั้น และคุณต้องให้สิทธิ์เขาบน GitHub เอง

## บทบาท

บทบาทบอก agent ของแต่ละคนว่าคนนั้นรับผิดชอบอะไร บทบาทสำเร็จรูปคือ **ฟรอนต์เอนด์**, **แบ็กเอนด์**, **ฐานข้อมูล / MCP** และ **กำหนดเอง** ใต้หัวข้อ **บทบาท** หัวหน้าแก้ prompt ของแต่ละบทบาทได้ (คลิกนอกกล่องเพื่อบันทึก) และเพิ่มบทบาทของตัวเองได้ คนอื่นเห็นข้อความเดียวกันแบบอ่านอย่างเดียว

สมาชิกแต่ละคนมีหนึ่งบทบาท หัวหน้าเลือกให้ในแถวของสมาชิก งานก็มีบทบาทของตัวเองได้ และ agent ใช้บทบาทของงานระหว่างทำงานนั้น

## ใครแก้อะไรได้

Taskmaster ไว้ใจทีมของคุณ: ใครที่มีสิทธิ์เขียนใน repository ก็แก้ข้อมูลทีมได้ ถ้าสองคนแก้งานเดียวกันพร้อมกัน คนที่ซิงก์ทีหลังสุดจะชนะสำหรับงานนั้น ดูบท "การซิงก์และการใช้งานออฟไลน์"

รายการ **ทักษะ** ในมุมมองทีมเก็บทักษะของ Claude Code ที่ทีมแชร์กัน ทุกคนเพิ่ม แก้ไข หรือลบได้ แต่ละคนเลือกเองว่าจะให้ agent โหลดหรือไม่ที่ **ใช้ทักษะของทีมใน agent** ในการตั้งค่า → Agents เพราะทักษะคือคำสั่งที่เพื่อนร่วมทีมเขียน ทักษะเรียกใช้เป็น `/team:ชื่อ`
